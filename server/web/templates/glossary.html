The competition

The model, the way it is trained and the exam are the same for everyone. The only thing an entry changes is the data the model learns from.

Curator also: entry, editor

What you enter: a program that is handed a pile of raw web pages it has never seen and {{howlong .Scale.EditSeconds}} on one GPU, and decides what to keep, what to cut, and in what order. It can be a few rules, a small model you trained, or an agent. Its code is public from the first round it plays.

Example: tidy keeps English prose, drops exact duplicates, cuts navigation lines, and shuffles what is left.
Round

One heat of the competition. A fresh random slice of web pages is drawn, every curator in the round edits that same slice, and the model is trained on each result and examined. Rounds run one at a time: one is drawn when an entry is waiting and the last has settled, and every {{.Interval}} regardless. Each has a number (round 6) and an ID ({{roundid 6}}: {{lower .Season.Title}}, official round 6).

Unedited also: raw, the baseline

The round's pages exactly as drawn, with nothing cut or reordered: what the model would learn from with no curator at all. The model is trained on the unedited pages too, and how it does on the exam is the mark every entry in that round is trying to beat.

Edit script

What a curator produces: a list of which pieces of which pages to keep, in what order, and how many times. It is plain data, not code, so anyone can train on it safely. At least {{pct1 $d.CopyFrac}} of what the model reads must be copied byte for byte from the round's pages: the competition is about choosing data, not writing it. Every script is published when its round settles.

The model also: the student

A small language model ({{.Scale.NLayer}} layers, {{.Scale.DModel}} wide) with fixed settings. It reads exactly {{compact .Scale.TrainTokens}} tokens of a script: too little and the data repeats, too much and the rest is cut off. It is trained from the same starting weights for every entry in a round, so the data is the only difference.

Exam

Made for each round after its draw, so nobody can know it in advance, the organisers included: text people published in the two hours after the draw (on Wikipedia, news sites, GitHub, Hacker News, Lemmy, Bluesky and Mastodon), and problems generated from the round's own random seed. It tests {{len .Season.ExamSources}} capabilities, each counting the same: {{range $i, $s := .Season.ExamSources}}{{if $i}}, {{end}}{{$s}}{{end}}. Practice rounds use the generated problems only.

Loss

How surprised the model is by the right text on the exam (the answer, the reply, the rest of the passage), on average per byte. Lower is better: a model that predicts the next word well is rarely surprised.

Bits per byte

The unit scores are measured in: how many bits the model needs, on average, to write down each byte of the exam's text. You don't need the maths: what matters is the difference between two scores.{{if worth}} For a sense of how big a difference is, the worth column turns it into how much more data it was worth.{{end}}

Gain

The score for one round: how much better the model does on the exam after learning from the curator's edit than from the unedited pages, in bits per byte. Each of the {{len .Season.ExamSources}} capabilities counts the same: the gain is the mean of the curator's gain on each. Higher is better. 0 means no better than doing nothing; below 0 means the curator made the data worse.

Example: a curator whose model does 0.07 bits per byte better on every capability has a gain of +0.07.

The standings

How rounds add up to a ranking.

Rating

A curator's average gain over the rounds it has played, adjusted for how hard each round's pages were, so an entry that happened to play only hard rounds isn't punished for it. The leaderboard is sorted by rating.

On the leaderboard it is the bar: it starts at the unedited pages, and longer is better.
± also: standard error, uncertainty

How far the rating might be from the curator's true level, given how much its gain moves from round to round. Two curators whose ratings are closer than their ± are hard to tell apart. It shrinks as a curator plays more rounds.

Worth also: multiplier
{{if not worth}}

The rating said another way: how many times as much unedited data the model would have needed to do as well. It is read off a curve measured by training the model on more and more unedited data. This season's curve has not been measured yet, so no worth is shown.

{{else}}

The rating said another way: a model trained on this curator's pick did as well as one trained on that many times as much unedited data. It is read off a curve measured by training the model on more and more unedited data, and never guessed beyond it: past the end of the curve it reads "more than", as in >8×.

1.00× means no better than unedited. 6× means the curator's data was worth six times as much raw data.{{end}}
Qualifying

A new entry's first {{$d.QualifyRounds}} rounds. It is ranked after {{$d.RatedRounds}}. Until then it is listed separately, under "not ranked yet", with a paler bar, because one or two lucky rounds can make a newcomer look better than it is.

Ladder

The {{$d.LadderSize}} curators run again in every round: the record holder, then the best-rated curators, at most one per person (the organisers' reference curators excepted). Playing the same rounds is what lets any two of them be compared on the same pages.

Record

A stricter title than first place. A challenger takes the record only by beating the holder head to head on rounds both played, by more than {{f2 $d.Margin}} bits per byte, in a statistical test that rules out a lucky streak. It is checked only at {{range $i, $l := $d.Rule.Looks}}{{if $i}}, {{end}}{{$l}}{{end}} shared rounds, never in between, so checking after every round cannot hand it to a lucky copy of the holder. The first record goes to the first curator to beat the unedited pages that way.

Reference curator

A curator entered by the organisers as a yardstick. identity changes nothing, so its gain should be about 0: a check that the scoring is fair. english and tidy are simple rule-based curators a serious entry should beat. Their code is public; stet fork stet/tidy copies one to start from.

Who does the work

Scores are made on verifiers' machines. Anyone can be one, and the rules are built so that no score needs the organisers' hardware. While volunteers are few, the organisers' own machines fill in, and every score they stand behind alone says so.

Verifier

Anyone who lends a GPU by running stet verify. Verifiers run curators and grade scripts. They cannot choose their work, never handle their own entry, and cannot see anyone else's results until the round settles. Everyone verifying →

Run

One verifier's machine running a curator on the round's pages, in a sandbox with no network, for up to {{howlong .Scale.EditSeconds}}. A run produces an edit script. Each entry gets {{$d.RunsPerEntry}} runs by different people when that many are around; if they differ by more than {{f2 $d.Tolerance.Run}} bits per byte, a third person runs it and the median counts.

Grade

One verifier training the model on one edit script and sitting it on the round's exam, against the unedited pages' score: the mean of what the established verifiers measured. Grading runs nobody's code: the script is plain data. A script is never graded only by the person whose run wrote it, except by the organisers' machine when nobody else is there.

Established

A verifier whose grades have agreed with other people's {{$d.EstablishAfter}} times{{if .Github}}, with a GitHub account at least {{$d.GithubDays}} days old linked{{end}}. Only established verifiers' grades make scores, and only they may run curators. Everyone else's grades are checks: published, compared, and counted towards becoming established. An account whose grades differ {{$d.MuteAfter}} times, and more than once for every ten that agreed, gets no work for {{$d.MuteDays}} days.

Organisers' machine

The organisers' own verifier accounts. They start out established so a season can begin, are marked on every page, and are checked like anyone else. However many machines they have, they count as one person. When nobody else is around, an organisers' machine may run a curator and grade it itself; such scores say so.

How sure a score is

Every score says how many people stand behind it, with one, two or three dots.

sealed

While a round is being run, the site and the API show none of its exam, scripts, grades or even its unedited score, and a verifier sees only the one job in hand. So no runner can copy another's run, and no grader can tune to anyone else's number. Everything is published at once when the round settles.

settled

The round is over: every entry has its score, and every run and grade behind it is public.

Confirmed

Two or more different people ran the curator on their own machines and got the same result, each run was graded by someone other than its runner, and more than one person's grades are behind the score. The strongest a score gets.

One runner · One grader

The runs agree, but they were all made by one person (one runner), or all graded by one person (one grader). The organisers' machines count as one person.

Run once graded by its own runner

Only one machine ran the curator, because nobody else was around. Graded by its own runner means that same machine also graded what it wrote; only the organisers' machine may do that, so a season can start. Such a score has been checked by nobody else yet, but its script is public, so anyone can re-grade it with stet score.

Runs differed

Two runs of the curator came out more than {{f2 $d.Tolerance.Run}} bits per byte apart. A third was asked for, and the score is the median. Curators that use the GPU or the clock can legitimately vary.

disputed outlier

Outlier (counted on a score as "1 differed"): a grade landed more than {{f2 $d.Tolerance.Grade}} bits per byte from the script's gain. It is published, and counts as a strike against that account. Disputed: two established verifiers measured different gains for one script and nobody was there to say which was right; the gain is midway, and neither is struck.

failed not run

Failed: every run of the curator crashed, ran out of time with nothing written, or wrote an invalid script, so the round scores a gain of 0 for it. A curator with two failed rounds in its last five stops being run. Not run: nobody could run it, or check a run of it, so the round does not count for it at all.

Where the pages come from

Nobody chooses a round's pages, and anyone can check that.

Draw

The moment a round's pages are picked. The time is announced in advance and falls on a fixed {{minutes .Season.DrawGrid}}-minute grid, so it can't be chosen to suit anyone. Entries must be in before it.

Beacon

{{.Season.Beacon.Name}}: a public source of random numbers run by others, which emits a new value every few seconds. The first value after the draw time picks the round's pages, the exam's generated problems and the model's starting weights. Nobody, organisers included, can know it in advance.

Crawl

Common Crawl, a public archive of billions of web pages. Each round draws a few files from its newest crawl, named when the round is announced. Every verifier fetches the pages from Common Crawl itself and checks them against the announcement.

Scale

The size of everything in a round: how big the model is, how much it reads, how many pages are drawn. Official rounds this season are run at {{.ScaleID}}. Smaller scales exist for quick practice on your own machine.

Season

A run of rounds under one fixed set of rules, model and way of making the exam. {{.Season.Title}} is the current one.
