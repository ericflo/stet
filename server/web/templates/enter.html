Enter the competition

You compete by writing a curator: a program that turns a pile of raw web pages into training data. Write one, test it on your own machine as often as you like, and enter it. Volunteers run it on pages nobody has seen, and the leaderboard ranks it against everyone else's by how much more a model learns from your data than from the raw pile.

Do this

  1. Install

    One command. It brings its own Python {{.Season.Environment.Python}}, PyTorch for your GPU, and every library a curator may use.

    {{template "install" .}}

  2. Start from a working curator

    A single file that runs as it is. It keeps the pages that read as writing, which is nearly all of them, so it scores about what the raw pages do: the gain is yours to find. Or start from a reference curator with stet fork stet/tidy.

    $ stet init my-curator && cd my-curator

  3. Score it on your own machine

    Once, fetch three hours of recent writing for practice exams to use. A few minutes, and no account.

    $ stet harvest

    Then this runs your curator on a practice round, trains the model on what it kept, sits the exam and prints your gain. A minute or two on a GPU.

    $ stet run

  4. Change it and run it again. And again.

    There is no limit on this and nothing is uploaded. It is the same harness, the same kind of exam and the same arithmetic the leaderboard uses.

    stet run --rounds 5
    Five rounds: a mean and its error, so you can tell an improvement from luck.
    stet run --scale {{.ScaleID}}
    The size official rounds are run at.
    stet run --round {{if $d.LastSettled}}{{$d.LastSettled}}{{else}}{{roundid 1}}{{end}}
    Replay any official round that has settled, and compare with what the board says.
    stet run --sandbox
    Exactly as a volunteer's machine will run it: same limits, no network. Linux.

  5. Submit

    {{if .Github}}Entering needs a GitHub account at least {{$d.GithubDays}} days old, so that one person is one entrant. {{end}}--dry-run lists every file that would be published.

    $ stet login --handle yourname{{if .Github}}
$ stet login --github{{end}}
$ stet submit --dry-run
$ stet submit

  6. Watch it run

    stet status, or your curator's page here. You do not need to keep anything running.

After you submit

You can close the laptop. Everything below happens on other people's machines.

  1. {{if .OnDemand}}usually within the hour{{else}}within {{.Interval}}{{end}}

    Your entry is drawn into a round

    {{if .OnDemand}}A round is drawn as soon as an entry is waiting and the last round has settled, and every {{.Interval}} regardless.{{else}}A round is drawn every {{.Interval}}, on the clock.{{end}} A public randomness beacon picks a fresh slice of the newest web crawl after entries are locked, so nobody has seen the pages, you and us included.

  2. during the round

    Volunteers run it and grade it

    Your curator gets {{howlong .Scale.EditSeconds}} on a machine with {{.Season.Machine.Cores}} cores, {{.Season.Machine.MemoryGB}} GB and one GPU. Two different people run it when two are around, and other people train the model on what it wrote. You see only "running" until the round settles.

  3. when it settles

    Your gain is published

    With every run, every grade and the edit script itself. Your code becomes public, under the MIT licence, the first time it is drawn.

  4. after {{$d.Qualify}} rounds

    You are ranked

    The best {{$d.Ladder}} curators, one per person, stay on the ladder and keep running in every round{{if gt .Season.References.OneIn 1}} (the organisers' reference curators take turns){{end}}. Beat the record holder over the rounds you share and the record is yours.

What a curator may be

The harness is yours. The limits are the machine and the clock, not the method.

the full brief →

A few rules

Twenty lines that keep what reads as writing, in every language, and cut the boilerplate around it already gain. The reference curators are this, and they are open.

A model you trained

Fine-tune a small model at home and run it over every chunk. Name up to {{bytes .Season.Assets.MaxBytes}} of public Hugging Face files and they are in place before the clock starts.

An agent

Serve your model inside the sandbox and point a harness at it. Node.js is there beside Python, and examples/agent is a complete one.

Anything that writes a script in time

Python {{.Season.Environment.Python}} and {{len .Season.Environment.Packages}} libraries are on every machine. It has to run on NVIDIA and AMD alike: use the GPU through PyTorch and it does.

Questions entrants ask

the rules, in full →
How many things can I try?

On your own machine, as many as you like: stet run is the leaderboard's own harness, practice rounds never change, and every official round can be replayed once it settles. Officially you may have {{$d.InPlay}} {{plural $d.InPlay "entry" "entries"}} in play at once, because each one costs volunteers GPU time, and submit as often as you like. Submitting an entry again under the same name replaces it; another name is another entry.

Do I need a GPU?

Not to enter: your curator is run on verifiers' machines. To develop one, a GPU turns a practice run from a long wait into a minute or two. Any NVIDIA or AMD card, or a Mac, will do for that.

What is the gain, exactly?

How much better a model trained on your edit does on the exam than one trained on the raw pages, on the same round, in bits per byte; higher is better. Three quarters of the exam is writing people published and one quarter is generated skills; inside each, every kind counts the same.{{if worth}} The board also shows it as a multiplier: how much more raw data the model would have needed to do as well.{{end}}

Can my curator write new text?

No. Everything the model reads is copied byte for byte from the round's pages: whole pages, pages with lines taken out, or pieces of at least {{.Season.MinCopyBytes}} bytes. The competition is about choosing and ordering data, not about bringing your own. It was measured: 16,000 tokens of text written in the exam's forms bought 0.004 bits per byte, 1.3 standard errors. That is too small and uncertain to earn a rule, so a script holds no text of its own.

Is the exam secret?

Nobody can know it in advance, the organisers included. Each round's exam is made at its draw: from text people published in three hours of the day before, picked by the draw, and from problems generated from the round's own random seed. A curator runs with no network and can add no text of its own, so the exam cannot reach the model through it. A practice round sits the same kinds of writing once you have run stet harvest.

What if my curator crashes or runs out of time?

The last complete script it wrote still counts, so write one early and improve it. With no script at all, that run counts 0, or as your worst finished run when that is below 0. A round in which most runs failed counts as the lowest gain any valid entry got in it, or 0 if that is lower.

Why is my code published?

So that anyone can check a curator does what the rules allow, and so that the next person can build on it. stet fork copies any curator on the board.
